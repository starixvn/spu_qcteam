- Spec: https://nexdev.net/projects/nap-special-delete/wiki/202302_TVS_Send_problem_customer_in_AbnormalAccount_request_to_CTS

- Có 2 loại: 
1. IssueType=11: 
 1.a Void by bet (TVSRequestID = NULL) 
 1.b Void by request (TVSRequestID <> NULL)
2. IssueType=13: void by request (TVSRequestID <> NULL)

- Void by bet (IssueType=11) và void by request (IssueType=13) không có Parlay
Chỉ có void by request IssueType=11 mới có Parlay

- IssueType=13 không có Sport

- Nếu vừa có void by request và bet thì ưu tiên request 

- Cancel request TVS: gửi RequestID=x, ReasonID=a -> sau đó đổi ReasonID=b nhưng vẫn giữ RequestID=x
Lúc này bên CTS_DatCenter: 
+ sẽ xóa ReasonID=a -> add ReasonID=b  
-> chỉ tồn tại PA b trong table CTSCustomerClassification, CTSCustomerClassification_History,TVSVoidRequest
+ Table TVSVoidRequest_Log thì vẫn lưu cả a và b

- Trường hợp có PA (from CTS) rồi, mark the same PA from TVS thì
+ Nếu không đổi perf: không insert history, TVS, maintable
+ Nếu đổi perf: insert, nhưng với CreatedBy là từ CTS

- TVS only mark PA for member, not for SMA
